# Руководство по внедрению тестирования CRM системы приема металла

## Краткое резюме анализа системы

### Основные компоненты системы:

1. **Модели данных:**
   - `Product` - Управление металлами (простые/составные)
   - `Element` - Химические элементы
   - `Operation` - Операции покупки/продажи/конверсии
   - `CashRegister` - Управление кассой
   - `Recount` - Система переучетов
   - `Conversion` - Конверсии металлов

2. **Livewire компоненты:**
   - `OperationManager` - Управление операциями
   - `ProductManager` - Управление продуктами
   - `CashRegisterManager` - Управление кассой
   - `RecountManager` - Система переучетов

3. **Критические бизнес-процессы:**
   - Прием металла с взвешиванием и оценкой
   - Расчет цен с учетом засоренности и ценовых шкал
   - Управление остатками и инвентаризация
   - Финансовые операции через кассу

## Пошаговое внедрение тестирования

### Этап 1: Подготовка инфраструктуры (1-2 дня)

#### 1.1 Настройка окружения
```bash
# Установка зависимостей для тестирования
composer require --dev phpunit/phpunit
composer require --dev laravel/dusk
composer require --dev mockery/mockery

# Настройка покрытия кода
composer require --dev phpunit/php-code-coverage
```

#### 1.2 Создание Factory классов
```bash
php artisan make:factory ProductFactory
php artisan make:factory ElementFactory  
php artisan make:factory UnitFactory
php artisan make:factory CashRegisterFactory
php artisan make:factory OperationFactory
```

#### 1.3 Настройка тестовой базы данных
```env
# .env.testing
DB_CONNECTION=sqlite
DB_DATABASE=:memory:
```

### Этап 2: Unit тесты моделей (3-4 дня)

#### Приоритет 1: Критические модели
1. **Product Model** - расчеты цен, валидация составных продуктов
2. **CashRegister Model** - операции с деньгами
3. **Conversion Model** - конверсии металлов
4. **Recount Model** - переучеты

#### Примерный план:
- День 1: ProductTest (составные продукты, ценовые шкалы)
- День 2: CashRegisterTest (транзакции, балансы)
- День 3: ConversionTest + RecountTest
- День 4: Element, Operation, OperationItem тесты

### Этап 3: Integration тесты (2-3 дня)

#### 3.1 Database Integration
- Тестирование связей между моделями
- Проверка каскадных операций
- Валидация constraints

#### 3.2 Livewire Component Integration
- Тестирование взаимодействия компонентов
- Проверка обновления состояния
- Валидация форм

### Этап 4: Feature тесты (4-5 дней)

#### Критические сценарии:
1. **Полный цикл покупки металла**
2. **Работа с составными продуктами**
3. **Конверсии и преобразования**
4. **Система переучетов**
5. **Управление кассой**

### Этап 5: Browser тесты (3-4 дня)

#### E2E сценарии:
1. Пользовательский интерфейс операций
2. Модальные окна и формы
3. Responsive дизайн
4. Валидация на клиенте

### Этап 6: Performance и Security тесты (2-3 дня)

#### Performance:
- Тестирование больших объемов данных
- Memory usage под нагрузкой
- Database query optimization

#### Security:
- Проверка авторизации
- Валидация ввода
- CSRF защита

## Автоматизация и CI/CD

### GitHub Actions Pipeline
```yaml
name: Tests
on: [push, pull_request]
jobs:
  tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup PHP
        uses: shivammathur/setup-php@v2
        with:
          php-version: 8.2
      - name: Install dependencies
        run: composer install
      - name: Run tests
        run: php artisan test --coverage
```

### Локальная автоматизация
Используйте созданный `run-tests.ps1` скрипт:
```powershell
# Запуск всех тестов
.\run-tests.ps1 -All

# Только Unit тесты с покрытием
.\run-tests.ps1 -Unit -Coverage

# Конкретный тест
.\run-tests.ps1 -Filter "ProductTest"
```

## Метрики и мониторинг

### Key Performance Indicators (KPI)
- **Code Coverage** - минимум 80% для критических компонентов
- **Test Execution Time** - не более 5 минут для полного набора
- **Failed Tests Rate** - менее 1% в production builds
- **Bug Detection Rate** - количество багов, найденных тестами

### Отчетность
1. **Еженедельные отчеты** о покрытии кода
2. **Ежемесячный анализ** производительности тестов
3. **Квартальный обзор** эффективности тестирования

## Распространенные ошибки и их тестирование

### 1. Финансовые расчеты
```php
// ❌ Потенциальная ошибка
$total = $weight * $price; // может быть float precision error

// ✅ Правильное тестирование
$this->assertEquals(10075.00, round($weight * $price, 2));
```

### 2. Остатки на складе
```php
// ❌ Опасно - отрицательные остатки
$product->decrement('stock', $quantity);

// ✅ Тестируем граничные случаи
$this->assertTrue($product->stock >= $quantity, 'Недостаточно остатков');
```

### 3. Процентное содержание элементов
```php
// ❌ Может превысить 100%
$totalPercentage = $elements->sum('pivot.percentage');

// ✅ Валидация в тестах
$this->assertLessThanOrEqual(100, $totalPercentage);
```

## Заключение

Внедрение комплексной системы тестирования для CRM приложения по приему металла критически важно для:

1. **Финансовой безопасности** - предотвращение ошибок в расчетах
2. **Стабильности системы** - раннее выявление проблем
3. **Качества кода** - поддержание высоких стандартов
4. **Скорости разработки** - уверенность при изменениях

Рекомендуется начать внедрение с наиболее критических компонентов (расчеты цен, операции с кассой) и постепенно расширять покрытие тестами всех функций системы.
