# Система переучета денег в кассе и продуктов на складе

## Описание системы

Система переучета предназначена для контроля и учета фактических остатков продуктов и элементов на складе, а также денежных средств в кассах. Система позволяет выявлять расхождения между учетными данными и фактическими остатками.

## Основные компоненты

### 1. Модели данных

#### Recount (Переучет складских остатков)
- `number` - уникальный номер переучета (автогенерация)
- `type` - тип переучета ('products' или 'elements')
- `status` - статус ('pending', 'completed', 'cancelled')
- `user_id` - ответственный пользователь
- `reason` - причина проведения переучета
- `notes` - дополнительные примечания
- `started_at` - время начала переучета
- `completed_at` - время завершения
- `total_discrepancy_amount` - общая сумма расхождений

#### RecountItem (Элементы переучета)
- `recount_id` - связь с переучетом
- `countable_type/countable_id` - полиморфная связь (Product или Element)
- `expected_quantity` - ожидаемое количество
- `actual_quantity` - фактическое количество
- `discrepancy` - расхождение (факт - ожидание)
- `unit_price` - цена за единицу на момент переучета
- `discrepancy_amount` - сумма расхождения
- `notes` - примечания к позиции

#### CashRecount (Переучет касс)
- `number` - уникальный номер переучета кассы
- `cash_register_id` - связь с кассой
- `user_id` - ответственный пользователь
- `status` - статус переучета
- `expected_balance` - ожидаемый баланс
- `actual_balance` - фактический баланс
- `discrepancy` - расхождение
- `reason` - причина переучета
- `notes` - примечания

### 2. Livewire компоненты

#### RecountManager
- Управление переучетами складских остатков
- Создание, просмотр, начало и завершение переучетов
- Редактирование позиций переучета

#### CashRecountManager
- Управление переучетами касс
- Создание, просмотр и завершение переучетов касс

### 3. Функциональность

#### Переучет складских остатков
1. **Создание переучета** - выбор типа (продукты/элементы), указание причины
2. **Автозаполнение позиций** - система автоматически создает позиции для всех товаров с остатками
3. **Ввод фактических данных** - пользователь указывает фактически подсчитанные остатки
4. **Расчет расхождений** - автоматический расчет разницы и суммы расхождений
5. **Завершение переучета** - обновление остатков в системе согласно фактическим данным

#### Переучет касс
1. **Создание переучета кассы** - выбор кассы, указание причины
2. **Фиксация ожидаемого баланса** - система запоминает текущий баланс кассы
3. **Ввод фактического баланса** - пользователь указывает результат пересчета наличности
4. **Корректировка баланса** - автоматическая корректировка баланса кассы в случае расхождений

## Workflow (Рабочий процесс)

### Переучет складских остатков

1. **Инициация** → Пользователь создает новый переучет
2. **Подготовка** → Система автоматически создает позиции для всех товаров с остатками > 0
3. **Начало** → Пользователь начинает переучет (фиксируется время начала)
4. **Выполнение** → Постепенное заполнение фактических количеств по позициям
5. **Завершение** → Все позиции заполнены, пользователь завершает переучет
6. **Обновление** → Система обновляет остатки согласно фактическим данным

### Переучет касс

1. **Инициация** → Создание переучета с выбором кассы
2. **Фиксация** → Система фиксирует текущий баланс как ожидаемый
3. **Подсчет** → Физический пересчет денежных средств
4. **Ввод данных** → Указание фактической суммы в системе
5. **Корректировка** → Автоматическое исправление баланса кассы

Система использует существующую систему ролей и разрешений:
- **Супер-админ, Админ, Бухгалтер** - полный доступ
- **Менеджер** - доступ к просмотру и созданию переучетов

## Интеграция с существующей системой

### Связи с моделями
- `Product::recountItems()` - позиции переучетов продукта
- `Element::recountItems()` - позиции переучетов элемента  
- `CashRegister::cashRecounts()` - переучеты кассы

### Автоматическое обновление остатков
При завершении переучета система автоматически обновляет:
- `Product::stock` - остатки продуктов
- `Element::stock` - остатки элементов
- `CashRegister::balance` - баланс кассы (с созданием транзакции)

## Генерация номеров

### Переучеты складских остатков
Формат: `REC-YYYY-NNNNNN`
Пример: `REC-2025-000001`

### Переучеты касс
Формат: `CRC-YYYY-NNNNNN`
Пример: `CRC-2025-000001`

## Отчетность и аналитика

### Типы расхождений
- **Излишек** (surplus) - фактический остаток больше учетного
- **Недостача** (shortage) - фактический остаток меньше учетного
- **Соответствие** (match) - фактический остаток равен учетному

### Финансовый учет
Система рассчитывает финансовое влияние расхождений:
- Сумма расхождений по каждой позиции
- Общая сумма расхождений по переучету
- Влияние на стоимость остатков

## Миграции

Созданы следующие таблицы:
- `recounts` - основная таблица переучетов
- `recount_items` - позиции переучетов
- `cash_recounts` - переучеты касс

## Демонстрационные данные

Сиддер `RecountSeeder` создает примеры:
- Переучет продуктов с небольшими расхождениями
- Переучет элементов (без фактических данных)
- Завершенный переучет кассы с расхождением

## Запуск системы

1. Выполнить миграции: `php artisan migrate`
2. Заполнить демо-данными: `php artisan db:seed --class=RecountSeeder`
3. Перейти в интерфейс по маршрутам выше
