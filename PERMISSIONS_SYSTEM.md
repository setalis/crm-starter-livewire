# Система разрешений

## Описание
В приложении используется система разрешений Spatie Laravel-Permission для управления доступом пользователей к различным функциям системы.

## Роли в системе

### 1. super-admin (Супер администратор)
- Имеет ВСЕ разрешения в системе
- Может управлять пользователями, ролями и разрешениями
- Имеет доступ ко всем разделам

### 2. admin (Администратор)  
- Имеет доступ ко всем разделам кроме управления пользователями
- Может управлять товарами, операциями, складом и т.д.
- Не может создавать/редактировать пользователей и роли

### 3. accountant (Бухгалтер)
- Ограниченный доступ к финансовым операциям
- Может работать с кассой, отгрузками, переучетами
- Имеет доступ к аналитике и отчетам

### 4. manager (Менеджер)
- Базовые права для торговых операций
- Может создавать продажи/покупки
- Ограниченный доступ к складу и кассе

## Как работает система разрешений

### При изменении разрешений роли:
1. Изменения сохраняются в базе данных
2. Очищается кеш разрешений  
3. Все пользователи с измененной ролью получают обновленные права при следующем запросе
4. **ВАЖНО**: Пользователям может потребоваться обновить страницу или перелогиниться

### Middleware для автоматического обновления:
- `RefreshUserPermissions` - автоматически проверяет и обновляет разрешения пользователей
- Добавлен ко всем веб-роутам для обеспечения актуальности разрешений

## Диагностика проблем

### Команды для проверки:
```bash
# Общая диагностика системы разрешений
php artisan permissions:check

# Проверка конкретного пользователя  
php artisan permissions:check --user-id=1

# Тестирование изменения разрешений роли
php artisan permissions:test-role-change manager manager@test.ru

# Очистка кеша разрешений
php artisan permission:cache-reset

# Полная очистка всех кешей
php artisan optimize:clear
```

### Если разрешения не применяются:

⚠️ **КРИТИЧЕСКАЯ ПРОБЛЕМА**: Система имела жесткое разделение интерфейса на админскую и менеджерскую панели, где менеджерские пункты меню НЕ проверяли разрешения.

**Исправлено:**
1. ✅ Добавлены проверки `@can()` для всех пунктов меню менеджеров
2. ✅ Обновлены роуты менеджерской панели с middleware проверки разрешений  
3. ✅ Расширены разрешения роли manager

**Если проблемы остаются:**
1. Обновите страницу (F5)
2. Перелогиньтесь в системе  
3. Очистите кеш: `php artisan permission:cache-reset`
4. Обновите сидер: `php artisan db:seed --class=RolePermissionSeeder`
5. Проверьте логи: `storage/logs/laravel.log`

## Добавление новых разрешений

### 1. Создание разрешения в сидере:
```php
// database/seeders/RolePermissionSeeder.php
'new_section' => [
    'new.permission' => 'Описание разрешения',
],
```

### 2. Назначение роли:
```php
$role->givePermissionTo('new.permission');
```

### 3. Использование в коде:
```php
// В контроллере/компоненте
if (auth()->user()->can('new.permission')) {
    // Код для пользователей с разрешением
}
```

### 4. В Blade шаблонах:
```php
@can('new.permission')
    <!-- Контент для пользователей с разрешением -->
@endcan
```

### 5. В роутах:
```php
Route::middleware('can:new.permission')->get('/route', Controller::class);
```

## Логирование
Все изменения разрешений логируются в `storage/logs/laravel.log` с подробной информацией:
- Какая роль изменена
- Старые и новые разрешения  
- Количество затронутых пользователей
- Время изменения

## Кеширование
Система использует несколько уровней кеширования:
- Кеш разрешений Spatie (автоматически очищается)
- Кеш времени последнего обновления разрешений
- Кеш проверки разрешений для каждого пользователя

Все кеши автоматически очищаются при изменении разрешений.
